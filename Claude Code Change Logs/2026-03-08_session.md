# Change Log — Session 2026-03-08

## Summary
Initial project creation for the Network Security Automation pipeline.

## Changes Made

### New Files Created
1. **`config/settings.ini`** — Configuration file for Nutanix, Panorama, and firewall API settings.
2. **`nutanix_vm_discovery/discover_vms.py`** — Python script that:
   - Connects to Nutanix Prism Central v3 API
   - Lists all VMs with pagination
   - Filters VMs by monitored subnet UUIDs
   - Compares against previous inventory JSON to identify new VMs
   - Performs reverse DNS lookups on new VM IPs
   - Writes a CSV report (Hostname, IP Address, FQDN, VM Creation Date)
   - Persists current inventory for next-run comparison
3. **`panorama_ts_agent/provision_ts_agents.py`** — Python script that:
   - Reads the new VMs CSV from the discovery script
   - Checks Panorama for existing TS-Agent entries (duplicate prevention)
   - Adds TS-Agent entries with hostname (ALL CAPS) as name and hostname.xyz.com as host address
   - Validates Panorama candidate configuration
   - Commits configuration to Panorama
   - Pushes configuration to managed firewalls
   - Waits 5 minutes for TS-Agent connections
   - Queries a sample firewall for TS-Agent connection status
   - Writes a status report CSV (VM Hostname, Agent Created Successfully, Connection Status)
4. **`requirements.txt`** — Python dependencies (requests, urllib3)
5. **`README.md`** — Full project documentation
6. **`CLAUDE.md`** — AI assistant context, role, goals, and session log

## Design Decisions
- Used Nutanix Prism Central v3 API (POST-based list endpoints) for VM discovery
- Used Panorama XML API for configuration management (set, commit, push)
- Inventory state stored as JSON keyed by VM UUID for deterministic diff between runs
- TS-Agent duplicate check queries Panorama before each add to ensure idempotency
- Job polling with configurable timeout instead of fixed sleep for commit/push operations
- 5-minute wait after push before checking TS-Agent connectivity on sample firewall
